> the crash test for AI coding agents

Your agent can read your .env, run shell commands and touch your databases. Crumple plants 18 traps modelled on real attacks, runs your own Claude Code, Codex or Gemini CLI setup against them, and shows you exactly where it breaks. Then it fixes it.

═[1]═ how it works

Scan it. Attack it. Fix it. Everything runs on your machine, and nothing real is ever at risk.

$ crumple scan
Reads your agent setup the way an attacker would: skip-permission modes, allow-rules that can run anything, MCP servers pinned to @latest, invisible text in rules files, repo hooks, committed .env files. A Safe Setup score in seconds. No API key, and nothing leaves your machine.
$ crumple attack
Builds 18 booby-trapped projects in a throwaway container and runs your own agent, with your own settings, against each one. Fresh fake keys every run. Its own DNS, HTTP and TLS listeners catch every way out.
$ crumple fix
Writes deny rules, installs the Crumple guard, pins your MCP tools and can lock it all in with managed settings. Then attack again and watch it hold.

═[3]═ crumple fix

Every failure ships with its fix. Then Crumple attacks again, so you can see the difference.

  • guard checks every command, edit, read, web fetch and MCP call before it runs. It parses commands the way the shell will, follows wrappers and inline scripts, and fails closed.
  • lock pins what every MCP server tells your agent and refuses any tool that changes later.
  • managed settings mean only your own hooks run, and nobody (the agent included) can switch the guard off.
  • audit writes every decision to a hash-chained log you can verify.
  • ci a GitHub check fails any pull request that makes your agent setup unsafe, with findings in code scanning.

We don't build or sell an AI agent. We crash-test them. That's why the results mean something.
