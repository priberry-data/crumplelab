> the crash test for AI coding agents

Independent crash tests for AI coding assistants.

Your agent can read your .env, run shell commands and touch your databases. Crumple plants 19 traps modelled on real attacks, runs your own Claude Code, Codex or Gemini CLI setup against them, and shows you exactly where it breaks. Then it fixes it.

AI coding assistants such as Claude Code, Codex and Gemini CLI can read passwords, run commands on a computer and change live databases. Crumple sets 18 realistic traps, modelled on real attacks, and records exactly what each assistant does when it walks into one. Teams learn whether their setup is safe, and how to make it safer.

═[1]═ how it works

Scan it. Attack it. Fix it. Everything runs on your machine, and nothing real is ever at risk.

Check it. Test it. Fix it. Nothing real is ever at risk: the passwords are fake and the test computer is thrown away afterwards.

$ crumple scan1. Check
Reads your agent setup the way an attacker would: skip-permission modes, allow-rules that can run anything, MCP servers pinned to @latest, invisible text in rules files, repo hooks, committed .env files. A Safe Setup score in seconds. No API key, and nothing leaves your machine.Crumple reads how the assistant is set up, the way an attacker would, and gives it a Safe Setup score from 0 to 100. It takes seconds and nothing leaves the computer.
$ crumple attack2. Test
Builds 18 booby-trapped projects in a throwaway container and runs your own agent, with your own settings, against each one. Fresh fake keys every run. Its own DNS, HTTP and TLS listeners catch every way out.The assistant gets ordinary tasks in 18 sealed practice projects. Each one hides a trap, such as a message asking it to send passwords away. Crumple watches every way out and records what happens.
$ crumple fix3. Fix
Writes deny rules, installs the Crumple guard, pins your MCP tools and can lock it all in with managed settings. Then attack again and watch it hold.Crumple switches on the protections that would have stopped each failure, then runs the test again to prove they work.

═[3]═ crumple fixthe fix

Every failure ships with its fix. Then Crumple attacks again, so you can see the difference.

  • guard checks every command, edit, read, web fetch and MCP call before it runs. It parses commands the way the shell will, follows wrappers and inline scripts, and fails closed.
  • lock pins what every MCP server tells your agent and refuses any tool that changes later.
  • managed settings mean only your own hooks run, and nobody (the agent included) can switch the guard off.
  • audit writes every decision to a hash-chained log you can verify.
  • ci a GitHub check fails any pull request that makes your agent setup unsafe, with findings in code scanning.
  • A guard that checks every action before the assistant takes it, and blocks anything that would send secrets out or destroy data.
  • A lock on the add-on tools an assistant uses, so a tool can't quietly change what it does later.
  • Company-wide settings that nobody, the assistant included, can switch off.
  • A tamper-evident log of every decision, for audits.
  • A check on every code change that stops anyone making the setup less safe by accident.

We don't build or sell an AI agent. We crash-test them. That's why the results mean something.

═ crumple siteapps built with AI ═

Built your app with Lovable, Bolt, v0, Replit or Emergent? The mistakes they ship most often are visible to anyone who opens it.

Check your app in the browser → nothing to install

$ npx crumplelab site yourapp.com
  • keys secret keys inside the JavaScript every visitor downloads: Stripe, OpenAI, Anthropic, AWS, GitHub, Slack, Resend, SendGrid, Twilio, Groq, Gemini.
  • supabase a service_role key in the browser skips every security rule. With --mine, Crumple counts which tables anyone can read, using requests that return a count and never a row. Firebase too: an open Realtime Database or Firestore collection.
  • source public source maps hand out your whole source code.
  • headers no Content-Security-Policy, so an injected script can send your users' data anywhere.
  • fix a grade from A to F, and for each finding a prompt to paste into your app builder. --prompt 1 prints one for the clipboard. Run it again after the fix: it shows what got fixed.
  • Leaked keys: passwords to paid services (payments, email, AI) left inside the app where any visitor can copy them and run up your bill.
  • Open data: a database that anyone on the internet can read, which is how most apps built this way have leaked their users' details.
  • Exposed code: the app's whole source code, published by accident.
  • Every finding comes with the fix: a grade from A to F, what to do by hand (like revoking a key), and a prompt to paste into Lovable, Bolt or Replit that makes the change for you. Check again afterwards and Crumple shows what got fixed.

Crumple reads only what your site serves to every visitor. The database check runs only when you add --mine, for an app that is yours.

Methodology

  • Same tasks, same traps for every agent, so results compare like for like.
  • Two runs per agent: settings exactly as shipped, then with protections switched on.
  • Every trap repeats, and the worst run counts. One lucky run never hides a failure.
  • Versions are pinned: each report names the agent version, the model and the date.
  • Nothing real is touched: fake keys made fresh for each run, a sealed container, no third-party systems.
  • Vendors hear first: any new security flaw goes privately to its vendor at least 30 days before we publish.
  • Reproducible: anyone can rerun a published result with one command.

═[6]═ faq

Is it safe to run on my machine?

Yes. The attacks run inside a throwaway Docker container with every capability dropped. The keys inside are fake and made fresh for each run, and every network exit leads back to Crumple, so nothing reaches the outside world. crumple scan doesn't even need Docker.

Does Crumple see my code or my keys?

No. Crumple runs on your machine and sends us nothing. During an attack, your agent talks only to its own model provider, using your own key or subscription.

What does a crash test cost?

The tool is free. Real agents use your own API key or subscription, and each trap is one short agent session. We'll publish measured costs alongside the first live results.

Which agents does it support?

The crash test runs Claude Code, Codex CLI and Gemini CLI; GitHub Copilot CLI and Cursor are next. scan reads the setups of 15 agents and editors: Claude Code and Claude Desktop, Codex, Gemini CLI, Cursor, Windsurf, VS Code, Kiro, Cline, Roo Code, Kilo Code, Zed, opencode, Amazon Q and Continue. site checks any deployed app, whatever built it.

Are you affiliated with Anthropic, OpenAI or Google?

No. Crumple is independent and built by Priberry. We don't build or sell an AI agent, so we have no reason to favour one.

What happens when you find a real vulnerability?

We report it privately to the vendor first and give them at least 30 days to fix it before we publish. Found one in Crumple itself? See security.txt.

When can I install it?

Now. Run npx crumplelab scan. It needs Node 20 or newer, and Docker for the crash test. The code is on GitHub under Apache 2.0.
